# UI 모션 — 화면 전환과 연출

> 비플레이 화면과 DOM UI의 모션만 다룬다. 색·타이포·컴포넌트는 [`UI_DESIGN.md`](./UI_DESIGN.md).
> **모션을 실제로 넣거나 고칠 때만 읽는다.** 일반 게임 로직·서버 작업에서는 필요 없다.

## 원칙

느리고 부드러운 모바일 앱보다 **빠르고 날카로운 게임 인터페이스**에 가깝다. 모션의 목적은 셋:

1. 지금 고를 수 있는 것을 알린다
2. 화면과 상태 변화를 잇는다
3. 경쟁성과 실시간성을 전달한다

장식 때문에 입력이 늦거나 정보가 늦게 뜨면 안 된다. **화면 전환을 400ms 이상 끌지 않는다.**

**FSM은 모션을 기다리지 않는다.** 상태는 즉시 바꾸고 모션은 시각적으로만 뒤따른다.
전환이 끝나야 다음 상태로 가는 구조를 만들면 네트워크 이벤트와 경합한다.

## 이징은 토큰, 지속시간은 아니다

`:root`에 이징만 토큰으로 뒀다:

- `--ease-out` — 감속. 진입·전환의 기본값
- `--ease-in-sharp` — 가속. 사망 낙하의 "툭 떨어지는" 무게감

지속시간은 토큰이 아니다. 버튼 0.12s부터 낙하 0.8s까지 성격이 제각각이라 몇 개로 뭉치면
**값이 바뀐다.** 각 규칙에 그대로 두고, 새로 넣을 땐 아래 표의 범위를 따른다.

| 대상 | 범위 | 현재 값 |
|---|---|---|
| 버튼 active / hover | 70~100ms / 120~160ms | .12s / .15s |
| 카드 hover | 150~220ms | .15s |
| 화면 진입(크로스페이드) | 220~280ms | .28s |
| 카드 떠오르기 | 220~340ms | .34s |
| 관전 대상 넘기기 | 200~280ms | .26s |
| 사망 낙하 → 관전 진입 | — | .8s → .55s |
| 목록 stagger | 45~65ms | 55ms (행 자체는 .3s) |
| 배경 이동 | 16~40초 | 미사용 |

## 화면별

**화면 진입** — `opacity 0→1` + `translateY(12px) scale(.97)→none`. 화면 안 요소는 35~55ms
간격으로 순차 등장할 수 있다. 복잡한 exit보다 안정적인 entry를 우선한다.

**버튼** — primary는 hover 시 `translateY(-2px)` + 약한 밝기 증가 + 짧은 청록 glow,
active는 `translateY(1px) scale(.985)`. secondary는 테두리와 글자만 밝아진다.
**지속 pulse는 사용자의 입력을 기다리는 primary 버튼 하나에만** 허용한다.

**게임 카드** — 비플레이 UI에서 가장 강한 인터랙션을 가져도 된다. hover 시 2px 상승,
1.015배 확대, 청록 테두리. 포인터 tilt를 넣는다면 정밀 포인터에서만, X·Y 최대 2.5도,
포인터가 나가면 즉시 원위치.

> 카드 미리보기를 위해 **실제 게임 인스턴스나 게임 루프를 돌리지 않는다.** 이미지·CSS 패턴·
> 정적 Canvas로 충분하다. 메뉴에서 게임을 돌리기 시작하면 루프가 두 개가 된다.

**대기실** — 방 코드는 진입 시 한 번만 점등. 플레이어 행은 **새로 들어온 사람만** 슬라이드
인하고 기존 목록 전체를 다시 애니메이션하지 않는다. 시작 버튼은 방장이 시작 가능할 때만
약하게 pulse하고, 카운트다운이 시작되면 즉시 멈춘다.

**카운트다운** — scale + opacity + 짧은 glow, 숫자마다 한 번의 충격감.
오버레이는 반투명으로 유지해 게임판이 준비되는 흐름을 가리지 않는다.

**결과** — 결과 패널 → 순위 행 → 개인 기록 → 다시 하기 순으로 들어온다. 순위 행은
45~65ms stagger. 1위·최고 기록에 짧은 glow를 한 번 줄 수 있다. **지속적인 축하 효과는 없다.**

## 플레이 중

플레이가 시작되면 정지하거나 숨긴다: 배경 장식 · 메뉴 입자 · 카드 장식 · 지속 pulse ·
사이트 헤더/푸터(`body.playing`).

플레이 중 허용되는 DOM 모션은 **짧고 기능적인 피드백뿐**이다 — HUD, 카운트다운, 사망,
관전 전환, 디버프 알림, 결과 전환. 이들은 전부 순수 CSS/DOM이라 게임 판정과 무관하다.

⚠️ **UI 모션은 게임 tick·시드·판정·동기화에 영향을 주지 않는다.** 이건 취향이 아니라
[`AGENTS.md`](../../AGENTS.md) 1-1 결정론 불변식의 UI 쪽 표현이다.

## Reduced Motion

`prefers-reduced-motion: reduce`에서 제거한다: 배경 이동 · 입자 · tilt · stagger · 흔들림 ·
지속 pulse · 큰 scale 변화. 화면 전환은 100~140ms opacity로 축소한다.

현재 구현은 사망 낙하·관전 전환·화면 흔들림·사망 섬광·디버프 흔들림/배너/구름을 끈다.
**끄되 정보는 남긴다** — 예를 들어 디버프 배너는 모션 없이 그냥 보이게 두고, 구름은
흐르지 않고 가리기만 한다. 무엇에 맞았는지 모르게 되면 안 되기 때문이다.

## 성능

- `transform`과 `opacity`를 우선한다.
- 무한 애니메이션 수를 최소화하고, **숨겨진 화면의 애니메이션은 멈춘다.**
- blur와 큰 box-shadow를 겹치지 않는다.
- 매 프레임 DOM 크기·위치를 반복 측정하지 않는다.
- GSAP 등 애니메이션 라이브러리를 추가하지 않는다.

## 비플레이 배경

메뉴·로비 뒤에 세 겹이 깔린다. 전부 `#bg-decor` 안에 있고 `pointer-events: none` · `aria-hidden`.

- **격자**(`.bg-grid`) — 불투명도 0.05, 36초에 한 칸(60px)씩 흐른다. 뷰포트보다 크게 깔고
  **정확히 한 칸만** 밀어야 반복 이음매가 안 보인다.
- **광원**(`.bg-glow`) — 오른쪽 아래에서 22초 주기로 느리게 숨 쉰다.
- **추종 광원**(`.bg-spot`) — 포인터를 늦게 따라간다. 아래 참조.

⚠️ 플레이 중에는 `visibility: hidden`이 아니라 **`display: none`** 이다. 숨기기만 하면
애니메이션이 계속 돌아 "숨겨진 화면의 애니메이션은 멈춘다"를 어긴다.

배경은 UI보다 느리게 움직인다(16~40초). 불투명도 0.08 이하로 글자 대비를 해치지 않는다.

### 포인터 추종 (`bgDecor.ts`)

**CSS만으로 안 되는 유일한 모션**이라 TS로 뺐다(포인터 좌표 예외). 지키는 규칙:

- **정밀 포인터에서만** 붙인다. 터치는 커서가 없어 광원이 마지막 탭 자리에 굳는다.
- `prefers-reduced-motion`에서는 아예 안 붙인다 — JS가 없어도 CSS 기본 좌표로 가만히 떠 있는다.
- **그라데이션 중심을 옮기지 않는다.** 원판 하나를 만들어 `translate3d`로 민다 —
  중심을 옮기면 매 프레임 다시 칠해야 하지만, transform은 합성만 하면 된다.
- **매 프레임 DOM을 측정하지 않는다.** 좌표는 이벤트가 준 값만 쓴다.
- **목표에 닿으면 rAF를 멈춘다.** 0.001px씩 영원히 다가가는 꼬리를 남기면 유휴 상태에서
  배경 장식 때문에 루프가 계속 돈다. 수렴은 `followStep`(순수 함수)이 계산하고
  `tests/BgDecor.test.ts`가 "반드시 멈춘다"를 지킨다.
- 플레이 중에는 좌표 갱신을 건너뛴다(장식이 이미 `display: none`이라 따라갈 이유가 없다).

즉시 따라붙이지 않는다. 감속으로 늦게 따라와야 배경처럼 읽히고, 커서에 딱 붙으면 싸구려로 보인다.

## 목록 stagger (`stagger.ts`)

순위 행과 대기실 플레이어 행이 한 줄씩 따라 들어온다. 모션은 CSS(`.enter` + `--i`)가 내고,
TS는 **누구를 · 몇 번째로** 만 정한다.

- **대기실은 새로 들어온 사람만** 움직인다. 목록을 통째로 다시 그리더라도 직전 명단과
  비교해 새 id에만 `.enter`를 붙인다. 전체가 매번 흔들리면 누가 왔는지 읽을 수 없다.
- 순서값은 목록 위치가 아니라 **새로 온 순서**다. 한 명만 들어오면 대기 없이 바로 뜬다.
- 결과는 라운드마다 새 목록이라 매번 1위부터 순서대로 들어온다.
- **지연에 상한을 둔다**(`STAGGER_MAX_INDEX`). 20명이면 마지막 행이 1초 뒤에 뜬다.
- `animation-fill-mode: both`가 필수다. 없으면 지연 동안 행이 먼저 보였다가 사라졌다 다시 뜬다.
- reduced-motion에서는 `animation: none` — 지연 없이 제자리에 있고 정보는 그대로 남는다.

`tests/Stagger.test.ts`가 "새로 온 사람만"과 상한을 지킨다.

## 아직 없는 것

입자 · 카드 tilt는 **아직 구현하지 않았다.** 넣는다면 위 규칙을 따르고, 특히
입자를 위해 별도 프레임워크나 게임 루프를 만들지 않는다 — CSS 또는 가벼운 독립 레이어로.

결과 화면의 **개인 기록 · 다시 하기 버튼**은 아직 순서에 안 들어가 있다(카드와 같이 뜬다).
넣을 때 `both`로 숨기면 버튼이 보이지 않는 채로 눌리므로 지연 대신 다른 방법을 찾을 것.

## 함정

**CSS 주석 안에 `*/`가 들어가면 주석이 거기서 닫힌다.** 파일 경로를 주석에 적을 때
별표를 쓰지 말 것(`games/*/config.ts` 같은 표기). 브라우저는 에러를 내지 않고 뒤따르는
규칙 몇 개를 조용히 버려서, 증상이 "색이 갑자기 안 먹는다"로만 나타난다.
