# UI 디자인 — 사이트 UI의 색·타이포·컴포넌트

> `packages/app`의 **DOM UI**(메뉴·로비·대기실·결과·공지)에만 적용된다.
> 게임 캔버스 안의 색과 연출은 각 게임 `config.ts` 소관이며 이 문서가 다루지 않는다.
> 화면별 모션은 [`UI_MOTION.md`](./UI_MOTION.md), 시스템 설계는 루트 [`DESIGN.md`](../../DESIGN.md).

## 방향

**Live Competitive Interface** — 정적인 웹사이트가 아니라 빠르게 반응하는 온라인 아케이드처럼
보여야 한다. 어두운 공간, 청록 네온, 짧고 날카로운 전환.

> 메뉴와 로비는 살아 움직이고, 실제 플레이 화면은 명확하고 절제되어야 한다.

TETR.IO의 속도감과 반응성은 참고하되 화면 구성·그래픽·고유 효과를 복제하지 않는다.

## 정본은 코드다

색과 이징의 **정본은 [`index.html`](./index.html)의 `:root` 블록**이고, 이 문서는 그 값의
*의미*를 설명한다. 값을 바꿀 땐 `:root`를 고치고 이 문서의 설명을 따라 고친다 — 반대 방향은 없다.

문서에 색값 표를 복제해두면 반드시 어긋난다. 그래서 여기엔 **용도만** 적는다.

알파가 섞인 배경(헤더, 오버레이, 선택된 탭 등)은 리터럴 `rgba()`를 쓰지 않고
`color-mix(in srgb, var(--토큰) N%, transparent)`로 토큰에서 계산한다. 리터럴을 남기면
토큰을 바꿔도 그 자리만 옛 색으로 남는다.

## 색의 의미

| 토큰 | 쓰는 곳 |
|---|---|
| `--bg-deep` | 가장 깊은 바닥. 밝은 배경 위의 **글자색**으로도 쓴다(청록 버튼, 오류 토스트) |
| `--bg` | 화면 기본 배경 |
| `--surface` / `--surface-elevated` | 카드 / 그 위에 뜨는 요소(게임 카드, hover 배경) |
| `--field` | 입력창·목록 행처럼 "값이 들어가는" 자리 |
| `--border` | 경계선 전부 |
| `--text-primary` / `--text-secondary` / `--text-muted` | 본문 / 보조 설명 / 라벨·비활성 |
| `--primary` / `--primary-strong` | **긍정적 주요 행동과 선택 상태** |
| `--danger` | 오류·사망·되돌릴 수 없는 행동 |
| `--warning` | 임박 경고(게이지가 곧 참 등) |
| `--rank` | 1위·최고 기록 |
| `--success` | 준비 완료·성공 상태 |

**강조색은 청록 하나다.** 한 화면에서 여러 강조색을 같은 비중으로 쓰지 않는다.

예전엔 primary가 빨강이라 **"입장" 버튼과 사망 섬광이 같은 색**이었다. 지금은 청록=행동,
빨강=오류·사망으로 갈려 색만 보고도 뜻이 읽힌다. 이 분리를 되돌리지 않는다.

**밝은 배경 위에는 어두운 글자를 얹는다.** `--primary`(청록)나 `--danger` 위에 흰 글자를
올리면 대비가 2점대로 떨어져 읽히지 않는다. `--bg-deep`을 글자색으로 쓴다.

### 대비 (WCAG AA = 4.5)

주요 조합 실측치. 색을 바꾸면 다시 재보고, **AA 아래로 내려가는 조합은 채택하지 않는다.**

| 조합 | 비율 |
|---|---:|
| Primary 버튼(청록 배경 + `--bg-deep` 글자) | 13.96 |
| `--text-primary` / `--text-secondary` / `--text-muted` on `--bg` | 17.71 / 12.24 / 6.68 |
| 방장 배지 · 「나」 배지 | 10.13 · 9.15 |
| 1위 금색 on `--surface` | 12.21 |
| 오류 토스트 | 6.14 |

## 타이포

제목은 굵고 압축되게, 본문은 빠르게 읽히게. 외부 웹폰트는 쓰지 않는다(시스템 글꼴).

**값이 바뀌거나 옮겨 적는 숫자는 고정폭**으로 둔다 — 방 코드, 생존 시간, 순위.
비례 글꼴이면 자릿수가 바뀔 때마다 폭이 흔들려 읽기 어렵다.

## 레이아웃 우선순위

1. 현재 화면의 핵심 행동
2. 현재 선택·상태
3. 보조 설명
4. 장식

플레이 화면에서는 **게임 캔버스가 모든 DOM UI보다 우선**한다.
좁은 화면에서는 장식 → 관전 칼럼 순으로 덜어내고 핵심 행동과 게임 화면 크기를 먼저 보장한다.

## 컴포넌트

- **Primary 버튼** = 입장 · 방 만들기 · 게임 시작 · 다시 하기. 그 외는 secondary(테두리만).
- **게임 카드**는 hover 시 2px 이하 상승, 1.015배 이하 확대. 강한 glow는 선택된 카드에만.
- **방 코드**는 고정폭 + 청록. 화면 진입 시 한 번만 점등한다.
- **플레이어 행**: 방장 배지만 채우고, 「나」는 테두리로만 구분한다.
  둘은 같은 줄에 함께 뜰 수 있어서 — 둘 다 채우면 강조가 서로 경쟁한다.
- **결과표**: 1위는 금색, 본인은 행 배경. **서로 다른 축이라 1위이면서 본인일 때 둘 다 읽힌다.**

## Game Boundary (넘지 않는 선)

사이트 UI는 다음에 **절대** 영향을 주지 않는다:

- 게임 tick · 시드 · 난수 스트림
- 충돌 판정 · 게임 결과
- 네트워크 동기화
- `IGame` · `IRenderer` · 프로토콜 계약

**UI 메타데이터 때문에 계약을 넓히지 않는다.** 게임 카드에 대표색을 넣고 싶어지면
`IGame`이 아니라 `packages/app`의 `GameRegistry`에 둔다 — 그건 앱의 표시 정보지 게임의 상태가 아니다.

플레이 중에는 장식·지속 모션을 정지하거나 숨긴다(자세한 건 [`UI_MOTION.md`](./UI_MOTION.md)).

## 접근성

- 모든 상호작용 요소에 `:focus-visible`. hover로만 전달되는 정보가 있으면 안 된다.
- **색만으로 상태를 전달하지 않는다.** 1위는 색+글자 크기, 선택된 탭은 색+배경 블록.
- 장식 레이어에는 `pointer-events: none`.
- `prefers-reduced-motion`에서 모션이 사라져도 정보와 기능은 그대로여야 한다.

## Don't

- TETR.IO의 화면·고유 효과를 복제하지 않는다.
- 애니메이션 라이브러리를 추가하지 않는다(CSS 우선, 동적 좌표가 필요할 때만 Web Animations).
- 모든 카드·버튼에 glow를 걸지 않는다.
- blur와 `backdrop-filter`를 겹겹이 쌓지 않는다.
- 색값을 이 문서에 복제하지 않는다.

## 모바일

**전용 UI를 따로 만들지 않는다.** 같은 화면이 좁아졌을 때 깨지지 않고, 게임판이 쓸데없이
작아지지 않게 하는 것까지가 범위다. 브레이크포인트는 하나(600px)뿐이다.

- **카드는 폰에서 화면 폭을 그대로 쓴다.** `min-width: 340px`를 풀지 않으면 360px 폰에서
  가로 스크롤이 생긴다. 세로로 넘치면 카드 안에서 스크롤한다(가로로 누운 폰).
- **여백은 폭만이 아니라 높이로도 줄인다.** 폰을 눕히면 판 크기를 정하는 건 세로다.
  폭 기준으로만 걸면 667×375 화면이 그대로 16px를 쓴다.
- **여백·간격의 정본은 CSS다.** `layoutPlayArea`가 `#play`에서 읽어 간다 — 상수를 양쪽에
  두면 폰에서 여백을 줄이는 순간 캔버스 계산이 어긋난다.
- **노치는 `env(safe-area-inset-*)`로 피한다**(`viewport-fit=cover`와 한 쌍).
- **확대는 막지 않는다.** 게임판은 이미 `touch-action: none`으로 빠져 있고, 공지·소개 글까지
  못 키우게 하면 안 된다. 조작 요소에만 `touch-action: manipulation`으로 두 번 탭 확대를 끈다.

조작 안내(어디를 눌러야 하는가)는 [`UI_MOTION.md`](./UI_MOTION.md) 참조.

## 터치 조작

게임은 방식의 **이름 하나만** 고른다(`GameRegistry`의 `touch`). 매핑·조작면·안내는
`touchSchemes.ts`에 한 줄로 묶여 있어 어긋난 조합이 애초에 표현되지 않는다.
없는 게임은 키보드 전용이다.

| 게임 | 방식 | 조작면 | 안내 |
|---|---|---|---|
| 커브 피버 | `halves` | 게임판 좌/우 절반을 누르고 있는다 | 반으로 갈린 오버레이 |
| 죽림고수 | `joystick` | **판 밖의 조이스틱 위젯**(8방향) | 위젯 자체가 보인다 |
| 무너지는 바닥 | `buttons` | **판 밖의 방향키 버튼 넷**(십자) | 버튼 + 가운데 칸의 "한 번에 한 칸" |

조작면은 두 종류로 갈린다. `halves`·`joystick`은 **누른 자리**가 방향이라 좌표를 방향으로
바꾸는 `TouchMapper`가 필요하고, `buttons`는 **누른 버튼**이 방향이라 매핑이라는 개념이
없다. 그래서 `SchemeSpec`은 판별 유니온이고, 버튼 방식에 매핑을 다는 실수는 타입에서 막힌다.

**무너지는 바닥에 미는 위젯을 쓰지 않은 이유** — 두 가지다.
1. 8방향은 대각선 구간에서 두 방향을 동시에 낸다. 격자는 한 tick에 한 칸만 가므로 게임이
   둘 중 하나를 골라야 하고, 그건 "민 방향과 다른 데로 갔다"로 보인다.
2. 더 큰 이유는 **세로 공간**이다. 미는 위젯은 경계가 눈에 안 보여 크게 만들어야 하는데,
   폰 세로 화면에서 그 높이가 곧 판을 밀어낸다. 버튼은 자기 크기가 곧 손가락 표적이다.

**조작을 판 위에 두지 않은 이유:** 손가락이 화면을 가린다. 조작 요소는 세로 화면에서는 판
아래 가운데, 가로 화면에서는 판 옆 왼쪽에 앉는다 — 정사각 게임판이 그 두 자리에 빈 공간을
남기기 때문이다.

### 판과 조작은 세로를 나눠 갖는다

⚠️ **조작 요소를 띄우면 `body`에 그 조작면의 클래스가 붙고(`controls-stick`/`controls-buttons`/
`controls-keypad`), CSS가 그만큼 `#play`의 아래 패딩을 키운다.** `layoutPlayArea`가 그 패딩을
읽어 판 크기를 정하므로 판이 저절로 그만큼 작아진다 — 숫자를 CSS와 JS 양쪽에 두지 않았기에
CSS 한 곳만 고치면 된다.

이름의 정본은 `touchSchemes.ts`의 **`SURFACE_CLASS`** 하나다(조작면 → 클래스). 코드가 붙이는
클래스와 CSS가 선언한 클래스가 같은지는 Keypad 테스트가 양방향으로 검사한다 — 어긋나면
판이 조작 위에 얹히는데 실기기에서만 드러나는 종류라서다.

이게 없으면 판은 뷰포트 **전체** 기준으로 가운데 정렬이라, 화면이 짧을수록 판 아래쪽이
조작 위젯에 먹힌다. 실제로 390×620에서 29px, 360×540에서 54px 겹쳤다(2026-08-03 폰 확인).

**조작면은 내가 살아 있는 동안에만 뜬다.** 관전 중이거나 라운드가 끝나면 걷는다 — 눌러도
아무 일이 없는 조작이 화면을 먹고 `←→ 관전` 힌트와도 겹친다. 걷히면 세로가 남으므로 관전
화면이 그만큼 커진다(360×540에서 324 → 344px).
⚠️ 이 판단은 `TouchControls.apply()` 한 곳에 모여 있고, 세션이 **`start()`에서
`setUsable(true)`를 반드시 다시 부른다.**
`ensureRunner`는 같은 게임이면 일찍 빠져나가므로, 거기서만 세우면 관전으로 걷힌 조작이
"다시 하기"에서 안 돌아온다.

세로 화면에서만 적용한다. 가로에서는 조작이 판 옆 여백에 앉으므로 세로를 먹지 않는다.
대신 그 여백이 좁아 버튼을 44px(손가락 표적 하한)로 줄인다 — 48px면 700×380에서 판
왼쪽 가장자리를 8px 덮었다.

⚠️ 조이스틱·방향키 버튼·숫자판은 화면 오버레이 사이에 얹히는 **조작 요소**다. 그래서 두
가지를 직접 되살려야 한다: `#ui`가 물려주는 `pointer-events: none`, 그리고 카운트다운보다
위에 오도록 하는 `z-index`. 둘 중 하나만 빠져도 손가락이 위젯을 통과하거나 막에 묻힌다.

⚠️ 방향키 버튼은 `<button>`이지만 **클릭음에서 뺀다**(`soundShell.ts`의 위임 핸들러가 `#dpad`
안쪽을 거른다). UI 버튼이 아니라 조작이라, 누를 때마다 딸깍거리면 한 판 내내 게임 소리가
그 밑에 묻힌다.

⚠️ **숫자판(`#keypad`)은 아직 그 예외에 안 들어가 있다.** 같은 `<button>`이고 같은 이유가
그대로 적용되는데(조작이지 UI가 아니다), 지금은 숫자를 칠 때마다 UI 클릭음과 게임의 타자음이
같이 난다. 거르려면 위임 핸들러의 제외 대상에 `#keypad`를 더하면 된다.

## 소리

효과음을 **코드로 합성한다**(`audio.ts`). 음원 파일을 두는 순간 에셋 파이프라인·
라이선스·로딩 실패 처리·번들 증가가 한꺼번에 딸려 오는데, 아케이드 효과음은
오실레이터 하나로 충분하다. 나중에 특정 소리만 파일로 바꾸려면 `SOUNDS` 표의 그 줄만
갈아끼우면 된다 — 부르는 쪽은 `play("click")`밖에 모른다.

| 소리 | 언제 | 결 |
|---|---|---|
| `click` | 버튼을 누를 때 | 짧은 한 음 |
| `count` | 카운트다운 숫자가 바뀔 때 | 같은 음 세 번 — 변하지 않아야 다음이 도드라진다 |
| `go` | 라운드가 시작될 때 | 올라가는 두 음 |
| `death` | 내가 죽을 때 | 떨어지는 세 음 |
| `result` | 판이 끝나 결과가 뜰 때 | 올라가는 아르페지오 |
| `pickup` | 죽림고수 — 아이템을 주울 때 | 짧게 올라가는 두 음 |
| `graze` | 커브 피버 — 니어 미스로 스칠 때 | 아주 짧고 작은 고음 |
| `fire` | 커브 피버 — 게이지가 꽉 차 쏠 때 | 각진 두 음 |
| `hit` | 남의 발사에 맞았을 때 | 낮게 떨어지는 두 음 |
| `crack` | 무너지는 바닥 — 칸이 뚫릴 때 | **잡음**을 높은 데서 낮은 데로 훑음 |

⚠️ `crack`만 유일하게 **오실레이터가 아니라 잡음**이다. 부서지는 소리는 음정이 없어서
오실레이터로는 아무리 겹쳐도 「삐」 소리지 「쩍」 소리가 안 난다. 화이트 노이즈 한 통을
만들어 두고 밴드패스로 2200Hz→300Hz를 훑어 내린다 — 그 궤적이 무너지는 결을 만든다.
`Tone.noise`가 붙은 소리는 `freq`가 음정이 아니라 **훑을 구간**으로 읽힌다.

아래 셋(`pickup`·`graze`·`fire`)은 **게임이 내는 슬러그**다. 게임은 `IGame.consumeSounds()`로
이름만 뱉고, 러너가 프레임 단위로 모아 앱에 넘기고, 앱이 같은 이름의 소리를 찾아 울린다.
표에 없는 이름은 조용히 지나간다 — 소리 없는 사건을 내는 게임이 생겨도 여기 손댈 일이 없다.
`hit`은 네트워크에서 온 사건이라 게임 계약을 거치지 않는다.

⚠️ `result`는 **멀티에서만** 낸다. 연습은 죽는 순간이 곧 결과라 사망음과 같은 프레임에
겹쳐 둘 다 뭉개진다. 소리를 하나 빼는 게 둘을 겹치는 것보다 낫다.

- **소리는 게임 로직이 아니다.** tick·시드·판정·동기화에 영향을 주지 않는다(모션 규칙과 같은 취급).
- **컨텍스트는 첫 재생 때 만든다.** 자동재생 정책상 사용자 제스처 전에는 소리가 안 나므로,
  미리 만들어 두면 잠든 채로 남는다. 탭을 옮기면 다시 잠들어서 재생마다 깨운다.
- **실패는 전부 무음이다.** 오디오가 없는 환경·노드 생성 실패·저장 차단 — 어느 것도 던지지 않는다.
  소리가 안 나는 건 게임을 못 하게 만들 이유가 아니다.
- **클릭음은 버튼마다 걸지 않는다.** `document`에 한 번 위임해서 동적으로 그려지는 게임 카드까지
  자동으로 포함된다. 버블 단계라 각 버튼의 핸들러보다 나중에 도는데, 덕분에 소리 토글을
  **켜는 클릭만 들리고 끄는 클릭은 조용하다** — 확인음을 따로 만들 필요가 없다.

**토글(`#sound-toggle`)이 헤더 밖에 있는 이유:** 소리를 가장 끄고 싶은 순간이 플레이
중인데 헤더는 그때 숨는다(`body.playing`). 그래서 헤더의 형제로 두고 헤더가
`padding-right`로 자리를 비워 준다. 플레이 중에는 **아래로 내려간다** — 우상단은 관전
칼럼(`#side-views`)이 쓰는 자리라, 판이 화면 폭을 꽉 채우는 창 비율(예: 900×700)에서
첫 관전창의 모서리를 덮는다. 상태는 아이콘만이 아니라 색으로도 구분하고, 라벨은
상태가 아니라 **누르면 일어날 일**을 말한다("소리 끄기"/"소리 켜기").
